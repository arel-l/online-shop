## Лабораторная работа №4. Spring Security, роли и логирование

### Цель работы
Подключить Spring Security к приложению, настроить пользователей и роли, разграничить доступ к REST API в зависимости от роли пользователя, а также реализовать логирование действий приложения.

### Реализованные возможности
**1. Spring Security**
- Подключена зависимость Spring Security.
- Настроена аутентификация пользователей с использованием HTTP Basic.
- Для хранения и проверки паролей используется BCryptPasswordEncoder.
- Настроена защита REST API от неавторизованного доступа.

**2. Пользователи и роли**
В приложении настроены четыре пользователя:

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | ADMIN |
| manager | manager123 | MANAGER |
| customer | customer123 | CUSTOMER |
| user | user123 | USER |

**3. Разграничение доступа к REST API**
Для запросов к `/api/products` настроены следующие права:

| HTTP-метод | Разрешённые роли | Операция |
|---|---|---|
| GET | ADMIN, MANAGER, CUSTOMER, USER | Просмотр товаров |
| POST | ADMIN, MANAGER | Добавление товара |
| PUT | ADMIN, MANAGER | Изменение товара |
| DELETE | ADMIN | Удаление товара |

При отсутствии аутентификации сервер возвращает HTTP 401 Unauthorized. При недостаточных правах доступа возвращается HTTP 403 Forbidden.

**4. Логирование**
Для логирования используется SLF4J и стандартная система Logback.

Реализовано:
- логирование запросов к REST API;
- запись информации об успешном выполнении операций;
- предупреждения при попытке обращения к несуществующим товарам;
- вывод сообщений в консоль и файл `logs/kursovaya.log`.

### Тестирование
Добавлены автоматические тесты для проверки настроек безопасности и разграничения доступа.
Проверяются:
- доступ к API без авторизации;
- доступ пользователей с различными ролями;
- добавление и изменение товаров;
- запрет удаления товаров пользователями без роли ADMIN;
- успешное удаление товара администратором;
- обработка неверных учётных данных.
Все 41 автоматический тест проекта успешно пройдены.

### CI/CD
В проекте присутствует конфигурация GitLab CI (`.gitlab-ci.yml`), предназначенная для автоматического запуска Maven-тестов.

### Запуск проекта
Для запуска приложения выполните:
./mvnw spring-boot:run


Для запуска тестов:
./mvnw clean test


REST API доступен по адресу:
http://localhost:8080/api/products


Для доступа к защищённым методам необходимо использовать HTTP Basic Authentication с учётными данными пользователя, имеющего соответствующую роль.
