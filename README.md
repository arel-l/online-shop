# Лабораторная работа № 3. Обработка исключений

## 1. Описание проекта
Проект представляет собой систему управления интернет-магазином, разработанную на Java с использованием Spring Boot.
Реализованы модели пользователей и товаров, взаимодействие с базой данных PostgreSQL с использованием Spring Data JPA, REST API для управления товарами, а также механизм обработки исключений.

## 2. Основные возможности
### 2.1. Работа с пользователями
- Представление пользователей с различными ролями.
- Разделение пользователей на администратора, менеджера и клиента.
- Поиск пользователя по электронной почте.
- Фильтрация пользователей по роли.
- Добавление и удаление пользователей.
- Получение статистики по ролям.
- Многопоточная обработка пользователей.

### 2.2. Работа с товарами
- Получение списка товаров.
- Получение товара по артикулу.
- Создание нового товара.
- Изменение существующего товара.
- Удаление товара.
- Фильтрация товаров по категории.
- Фильтрация товаров по минимальной и максимальной цене.
- Проверка корректности данных товара.
- Проверка уникальности артикула.

### 2.3. REST API

Для взаимодействия с товарами реализованы HTTP-операции:

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/products` | Получение списка товаров |
| GET | `/api/products/{article}` | Получение товара по артикулу |
| POST | `/api/products` | Создание товара |
| PUT | `/api/products/{article}` | Изменение товара |
| DELETE | `/api/products/{article}` | Удаление товара |

Для фильтрации списка товаров используются параметры запроса `category`, `minPrice` и `maxPrice`.

## 3. Обработка исключений
Для обработки ошибок разработан отдельный пакет `exception`, содержащий собственные классы исключений:
- `ProductNotFoundException` — возникает, если товар с указанным артикулом не найден.
- `ProductAlreadyExistsException` — возникает при попытке добавить товар с уже существующим артикулом.
- `InvalidProductDataException` — возникает при передаче некорректных данных товара.

### 3.1. Глобальный обработчик исключений
Класс `GlobalExceptionHandler` расположен в пакете `exception.handler`.
Для обработки исключений используется `@RestControllerAdvice`, позволяющая централизованно перехватывать исключения, возникающие при обработке HTTP-запросов.

Обработчик возвращает следующие HTTP-статусы:

| Исключение | HTTP-статус | Описание |
|---|---|---|
| `ProductNotFoundException` | 404 Not Found | Товар не найден |
| `ProductAlreadyExistsException` | 409 Conflict | Товар с таким артикулом уже существует |
| `InvalidProductDataException` | 400 Bad Request | Некорректные входные данные |
| Необработанное исключение | 500 Internal Server Error | Внутренняя ошибка сервера |

Таким образом, ошибки обрабатываются централизованно, а клиент REST API получает понятное сообщение и соответствующий HTTP-статус.

### 3.2. Проверка входных данных
Класс `ProductRequestMapper` преобразует данные HTTP-запроса в объекты товаров.

При преобразовании выполняются проверки:
- наличие обязательных полей;
- корректность артикула;
- корректность цены;
- отсутствие отрицательного количества товара;
- соответствие типа товара поддерживаемым значениям.

При обнаружении некорректных данных выбрасывается `InvalidProductDataException`.

## 4. Структура проекта

### Пакет `controller`
- `ProductController` — обработка HTTP-запросов к REST API товаров.
- `ProductRequestMapper` — преобразование данных запросов в объекты товаров.

### Пакет `repository`
- `ProductRepository` — интерфейс репозитория товаров.
- `ProductJpaRepository` — репозиторий Spring Data JPA.
- `OrderRepository` — интерфейс репозитория заказов.

### Пакет `repository.impl`
Содержит реализации репозиториев, работающие с данными в памяти для соответствующих сценариев приложения и тестирования.

### Пакет `service`
Содержит интерфейсы сервисов пользователей, товаров, заказов и многопоточной обработки.

### Пакет `service.impl`
Содержит реализации сервисов, в том числе сервис товаров, работающий с JPA-репозиторием, и тестовые реализации сервисов.

### Пакет `exception`
Содержит собственные классы исключений для обработки ошибок при работе с товарами.

### Пакет `exception.handler`
- `GlobalExceptionHandler` — глобальный обработчик исключений REST API.

### Основные классы
- `KursovayaApplication` — точка входа в приложение.
- `Product` — модель товара.
- `ProductEntity` — сущность товара для работы с JPA.
- `Order`, `OrderItem`, `Payment`, `ReturnItem` — модели, связанные с заказами, позициями заказов, оплатой и возвратами.

## 5. Архитектура приложения
В проекте используется разделение ответственности между слоями:
1. **Controller** принимает HTTP-запросы и формирует ответы.
2. **Mapper** преобразует входные данные запросов в объекты приложения.
3. **Service** реализует бизнес-логику.
4. **Repository** предоставляет операции доступа к данным.
5. **Entity** описывает сущности, сохраняемые в базе данных.
6. **Exception Handler** централизованно обрабатывает исключения.
7. **Database** — PostgreSQL, используемый для постоянного хранения данных.

## 6. Тестирование
Для проверки приложения используются автоматизированные тесты и ручное тестирование REST API.

Автоматизированные тесты проверяют:
- создание и поиск товаров;
- проверку повторяющихся артикулов;
- изменение и удаление товаров;
- фильтрацию товаров по цене и категории;
- создание, поиск, изменение и удаление заказов;
- работу модели пользователя;
- загрузку тестового контекста Spring Boot;
- обработку исключений `ProductNotFoundException`;
- обработку исключений `ProductAlreadyExistsException`;
- обработку исключений `InvalidProductDataException`;
- обработку непредвиденных исключений.

Тесты сервисов используют данные в памяти. Тестовый контекст настроен без автоматической конфигурации подключения к базе данных.

### 6.1. Проверка REST API через Postman
С помощью Postman проверяются HTTP-запросы к REST API:
- получение списка товаров;
- получение несуществующего товара;
- добавление товара;
- добавление товара с повторяющимся артикулом;
- передача некорректной цены;
- передача отрицательного количества;
- обновление товара;
- удаление товара;
- фильтрация по цене;
- передача некорректного диапазона цен;
- передача неизвестного типа товара.

Проверяется соответствие полученных HTTP-статусов ожидаемым результатам.

## 7. Запуск проекта
Для сборки и запуска используется Maven Wrapper.
Запуск тестов в PowerShell:
```powershell
.\mvnw.cmd clean test
```

Запуск приложения:
```powershell
.\mvnw.cmd spring-boot:run
```

После запуска REST API доступен по адресу:
[http://localhost:8080/api/products](http://localhost:8080/api/products)
Для работы с PostgreSQL необходимо настроить подключение к базе данных в конфигурации приложения.
