# Лабораторная работа № 2. Взаимодействие с базой данных. Spring Data JPA. Разработка REST-сервиса

## 1. Описание проекта

Проект представляет собой систему управления интернет-магазином, разработанную на Java с использованием Spring Boot.
Во второй лабораторной работе проект расширен за счёт взаимодействия с базой данных PostgreSQL с использованием Spring Data JPA и разработки REST API для управления товарами.

## 2. Основные возможности

### 2.1. Работа с пользователями

- Представление пользователей с различными ролями.
- Разделение пользователей на администратора, менеджера и клиента.
- Поиск пользователя по электронной почте.
- Фильтрация пользователей по роли.
- Добавление и удаление пользователей.
- Получение статистики по ролям.
- Многопоточная обработка пользователей.

### 2.2. Работа с товарами

- Получение списка товаров.
- Получение товара по артикулу.
- Создание нового товара.
- Изменение существующего товара.
- Удаление товара.
- Фильтрация товаров по категории.
- Фильтрация товаров по минимальной и максимальной цене.

### 2.3. REST API

Для взаимодействия с товарами реализованы HTTP-операции:

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/products` | Получение списка товаров |
| GET | `/api/products/{article}` | Получение товара по артикулу |
| POST | `/api/products` | Создание товара |
| PUT | `/api/products/{article}` | Изменение товара |
| DELETE | `/api/products/{article}` | Удаление товара |

Для фильтрации списка товаров используются параметры запроса, например `category`, `minPrice` и `maxPrice`.

## 3. Структура проекта

### Пакет `model`

Содержит модели пользователей и перечисление ролей:

- `User` — базовый абстрактный класс пользователя.
- `AdminUser` — администратор.
- `ManagerUser` — менеджер.
- `CustomerUser` — клиент.
- `UserRole` — перечисление ролей пользователей.

### Пакет `controller`

- `ProductController` — обработка HTTP-запросов к REST API товаров.

### Пакет `repository`

- `ProductRepository` — интерфейс репозитория товаров.
- `ProductJpaRepository` — репозиторий Spring Data JPA.
- `OrderRepository` — интерфейс репозитория заказов.

### Пакет `repository.impl`

Содержит реализации репозиториев, работающие с данными в памяти для соответствующих сценариев приложения и тестирования.

### Пакет `service`

Содержит интерфейсы сервисов пользователей, товаров, заказов и многопоточной обработки.

### Пакет `service.impl`

Содержит реализации сервисов, в том числе сервис товаров, работающий с JPA-репозиторием, и тестовые реализации сервисов.

### Основные классы

- `KursovayaApplication` — точка входа в приложение.
- `Product` — модель товара.
- `ProductEntity` — сущность товара для работы с JPA.
- `Order`, `OrderItem`, `Payment`, `ReturnItem` — модели, связанные с заказами, позициями заказов, оплатой и возвратами.

## 4. Архитектура приложения

В проекте используется разделение ответственности между слоями:

1. **Controller** принимает HTTP-запросы и формирует ответы.
2. **Service** реализует бизнес-логику.
3. **Repository** предоставляет операции доступа к данным.
4. **Entity** описывает сущности, сохраняемые в базе данных.
5. **Database** — PostgreSQL, используемый для постоянного хранения данных.

Для автоматизированного тестирования предусмотрены тестовые реализации сервисов и репозиториев, позволяющие проверять бизнес-логику без необходимости изменять данные в PostgreSQL.

## 6. Тестирование

Автоматизированные тесты проверяют:

- создание и поиск товаров;
- проверку повторяющихся артикулов;
- изменение и удаление товаров;
- фильтрацию товаров по цене и категории;
- создание, поиск, изменение и удаление заказов;
- работу модели пользователя;
- загрузку тестового контекста Spring Boot.

Тесты сервисов используют данные в памяти. Тестовый контекст настроен без автоматической конфигурации подключения к базе данных.

## 7. Запуск проекта

Для сборки и запуска используется Maven Wrapper.

Запуск тестов в PowerShell:

.\mvnw.cmd clean test

Запуск приложения:

.\mvnw.cmd spring-boot:run

После запуска REST API доступен по адресу:

http://localhost:8080/api/products

Для работы с PostgreSQL необходимо настроить подключение к базе данных в конфигурации приложения.
